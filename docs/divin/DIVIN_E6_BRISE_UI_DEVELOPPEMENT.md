# Développement — E6, interface de fuite de Brisé

18 octobre 2026, worktree local divin V5. Cette tranche raccorde l’interface au Store; elle ne clôt pas E6. Aucun commit, push ou publication.

## Source et comportement visible

L06 p.163 décrit Move (Flee), puis une Action Sprint avec un Test d’Athlétisme Intermédiaire (+2 DR); la distance du Sprint ajoute Run + DR en yards. Run vaut 4 × M. L06 p.185–186 impose de fuir puis sprinter tant que le personnage reste visible d’au moins un ennemi; une Action ultérieure pour mieux se cacher est facultative. Les valeurs de distance sont rendues en « mètres de jeu » à valeur numérique égale aux yards, selon la convention DIV-03. Le reçu Store conserve sa provenance source et les faits explicitement fournis par le MJ.

Le panneau commun apparaît dans Jouer pour chaque participant actif ou non portant Brisé. Le contrôle ne déduit ni ligne de vue, ni engagement, ni déplacement spatial. Le MJ doit confirmer la visibilité avant/après; Flee exige une liste d’ennemis engagés explicitement vide et bloque une liste non vide ou indéterminée. Le mode Walk/Run est explicite. Sprint exige le Move(Flee) préalable, un jet d100 et, si le Test partagé le demande, un choix explicite entre garder et inverser le résultat. Calculer reste pur; Appliquer passe par `Store.applyBrokenEscape`.

Les faits de brouillon et les jets sont invalidés lorsque la clé du Tour ou la révision locale change; le panneau affiche le Tour/clé courants et désactive l’application d’un aperçu périmé.

Quand le MJ établit que le personnage est déjà hors de vue, « Enregistrer le fait pour ce Tour » appelle `Store.confirmBrokenEscapeVisibility`. Cette attestation durable et sans quota ne crée pas de déplacement; elle permet au Tour de suivre son état canonique. Elle ne neutralise pas le blocage MIDTURN. Si l’Action a été consommée avant l’acquisition de Brisé, `DIV-BROKEN-MIDTURN-01` reste bloqué en attente d’une décision MJ explicite pour cette occurrence, sans Action supplémentaire et sans report automatique.

Hide n’est proposé qu’après confirmation hors de vue et reste facultatif. Le panneau ne lance pas ce Test : il prépare une compétence Discrétion/Stealth déjà résolue dans la fiche dans le formulaire Résolution standard. La préparation transmet `v5Context.isAction:true`, `runningOrHiding:true` et `involvesMovement:false`, afin que la résolution le traite comme l’Action facultative de se cacher et applique le quota du Tour. Sans compétence résolue, l’interface explique ce manque au lieu d’inventer un score ou un jet.

Les formulaires Prière, sort et Résolution exposent également le fait explicite `brokenEscapeFacts.visibleToAnyEnemy` aux aperçus Store pour les personnages Brisés. Pour un Test non-attaque de type Compétence, Défense ou Opposition, hors réaction canonique, le formulaire Résolution demande maintenant explicitement si le Test consomme l’Action du Tour (Oui/Non/À préciser) et transmet le choix via `v5Context.isAction`; Hide force `v5Context.isAction:true` et affiche son coût Action connu en lecture seule, sans choix Non. Le choix de visibilité reste un fait de formulaire; un simple aperçu ne le persiste pas. Le panneau principal est monté dans `js/ui/workspace-view.js`, les contrôles de formulaire réutilisent `js/ui/v5-broken-escape-panel.js`, les appels Prière sont raccordés dans `js/ui/v5-divine-panel.js`, et les nouveaux modules sont précachés par `sw.js`.

## Vérifications et limites

Vérifications de développement exécutées ici : `node --check` et `git diff --check` sur les modules UI. Le rouge initial d’aperçu précoce est conservé dans `tmp/divin/brise-flee-sprint-browser-render-red/receipt.json` : visibilité absente ou visible refusée par le Store, état inchangé, mais aucun avis `role=alert` ou contenu live dans Résolution. La première relance après correction a confirmé pour les deux cas un avis accessible, aucune pilule de résultat, aucun bouton Appliquer et aucun changement d’état. L’investigation a établi que `workspace-view.js` effaçait le refus avant rendu, car ces retours précoces ont `input.targetId` mais aucun `targetId` de premier niveau; la comparaison de cible consulte désormais aussi `preview.input.targetId` tout en conservant l’invalidation sur vrai changement de cible. Aucun faux Test n’a été observé dans ce rouge : l’aperçu avait été effacé avant rendu. Le faux résultat « Échec · DR +0 » était un risque de lecture du rendu complet face à une structure minimale, pas un effet constaté. Le contrôleur a également confirmé que Hide transmet `isAction:true`, `runningOrHiding:true` et `involvesMovement:false`, puis bloque sur `BROKEN_ESCAPE_ACTION_SPENT` sans mutation.

Le dernier test ciblé, `tmp/divin/brise-flee-sprint-render-fix-check-2/receipt.json`, a révélé une autre lacune : après Sprint, un Test générique de compétence sans `isAction` était accepté (`ready:true`). Le formulaire Résolution expose maintenant le choix Action/Non-Action/À préciser pour les Tests non-attaque de type Compétence, Défense et Opposition, sauf réaction canonique; Hide force `v5Context.isAction:true` et affiche son coût Action connu en lecture seule, sans choix Non. Le développeur signale 31/31 tests core ciblés verts; le contrôle browser final passe le parcours Hide → blade → Compétence : Hide reste Action verrouillée et le choix tri-état réapparaît après changement d’action (`tmp/divin/brise-flee-sprint-control-final/receipt.json`). La recette globale lancée par le principal reste en attente. Le scénario cloud complémentaire `tests/divin-v5-broken-escape-cloud-scenarios.mjs` couvre la synchronisation du reçu de Prière/Courroux et le refus mid-turn via `standardTurnActions`; il n’a pas été lancé ici.

Fuite engagée non exécutée : la UI bloque le cas et indique que Momentum, attaque gratuite et attribution de Brisé par les ennemis engagés restent à raccorder. Les faits spatiaux restent MJ. L’attestation hors de vue renseigne le Tour courant uniquement. Une acquisition de Brisé en milieu de Tour reste bloquée; aucune dérogation n’est proposée dans l’interface. Les autres clauses E6, la récupération générale et les lignes restantes de la source restent hors clôture.
